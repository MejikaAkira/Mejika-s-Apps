# GUI実装提案（LogSense v5）

## 1. 実装方針

### 使用ライブラリ
- **PyQt6**: モダンなGUIフレームワーク
- OpenCV（`cv2`）は画像処理のみ使用（表示はPyQtで行う）

### アーキテクチャ
- `app.py`: GUIアプリケーション（メインウィンドウ、コントロール）- **ルートディレクトリ直下に作成**
- `video_process/realtime_video_processor.py`: 既存の処理クラスをそのまま使用
- スレッド分離: GUIスレッドと処理スレッドを分離

## 3. 実装する機能

### コントロールボタン
1. **開始ボタン**: `RealtimeVideoProcessor.start()`を呼び出し
2. **停止ボタン**: `RealtimeVideoProcessor.stop()`を呼び出し
3. **録画ON/OFF**: 保存機能の有効/無効（将来実装）
4. **ネットワーク送信ON/OFF**: 送信機能の有効/無効（将来実装）

### 画像表示

#### 元フレーム
- **リアルタイム動画**: カメラから取得したオリジナルのフレームをリアルタイムで表示
- **表示方法**: 処理の成功/失敗に関係なく、`RealtimeVideoProcessor.frame_queue`から直接取得したフレームを表示
  - 処理結果を待たずに、カメラからの生フレームを表示
  - 処理が失敗しても、元フレームは常に表示される
- **タイムスタンプ表示**: 画像表示エリアの外部（画像の下）に時刻（`HH:MM:SS.mmm`形式）を表示
- タイマーで定期的に更新（例: 30-60FPS）

#### 差分画像
- **表示モード**:
  - **リアルタイムモード**: 処理された差分画像をリアルタイムで表示（デフォルト）
  - **再生モード**: 過去のフレームをスライダーで選択して表示
- **表示方法**: `RealtimeVideoProcessor.frame_buffer`から処理結果を取得して表示
  - 処理が成功した場合のみ、差分画像を表示
  - 処理が失敗した場合、エラーメッセージを表示
- **タイムスタンプ表示**: 画像表示エリアの外部（画像の下）に時刻（`HH:MM:SS.mmm`形式）を表示
- **エラーメッセージ表示**: 画像表示エリアの枠外（タイムスタンプの下）にエラーメッセージを表示
  - 「処理中...」（処理開始直後）
  - 「差分が検出されませんでした」（処理成功、差分なし）
  - 「位置補正に失敗しました」（位置補正エラー）
  - 「処理エラー: [詳細]」（その他のエラー）
- **再生スライダー**: 差分画像エリアの下部に配置（再生モード時のみ有効）
  - スライダーを操作すると、過去のフレームを表示
  - リアルタイムモード時はスライダーを非表示または無効化
- **自動リセット**: 録画開始時に、差分画像をリアルタイムモードに自動リセット

#### 表示設定
- `config.json`の`realtime_video.display.show`に基づき表示:
  - `"both"`: 元フレームと差分画像を並列表示
  - `"original"`: 元フレームのみ
  - `"difference"`: 差分画像のみ

### 統計情報表示
- **FPS**: フレーム処理速度
- **差分ピクセル数**: 検出された差分ピクセル数
- **差分率**: 差分ピクセル率（%）
- **処理時間**: 1フレームあたりの処理時間（ms）
- **フレーム番号**: 現在のフレーム番号

## 4. 実装の詳細

### クラス構成
```python
class MainWindow(QMainWindow):
    """メインウィンドウ"""
    - コントロールパネル
    - 画像表示エリア
    - 統計情報表示エリア

class VideoDisplayWidget(QWidget):
    """画像表示ウィジェット"""
    - OpenCV画像をPyQtで表示
    - リサイズ対応
    - タイムスタンプ表示（画像表示エリアの外部、画像の下）

class DifferenceDisplayWidget(QWidget):
    """差分画像表示ウィジェット"""
    - リアルタイムモード/再生モードの切替
    - 再生スライダー
    - タイムスタンプ表示（画像表示エリアの外部、画像の下）
    - エラーメッセージ表示（画像表示エリアの枠外、タイムスタンプの下）

class StatsWidget(QWidget):
    """統計情報表示ウィジェット"""
    - FPS、差分情報などの表示

class FrameHistoryBuffer:
    """過去フレームのバッファ（再生モード用）"""
    - リングバッファで過去フレームを保持
    - 最大保持フレーム数を設定可能
```

### スレッド処理
- **メインスレッド**: GUI更新（PyQt）
- **処理スレッド**: `RealtimeVideoProcessor`の既存スレッド
- **通信**:
  - **元フレーム**: `frame_queue`から直接取得（処理の成功/失敗に関係なく表示）
  - **差分画像**: `frame_buffer`経由で処理結果を取得（処理成功時のみ表示）
- **更新**: `QTimer`で定期的に`frame_queue`と`frame_buffer`をチェック

### 過去フレームの保持（再生モード用）
- **FrameHistoryBuffer**: 過去のフレームを保持するリングバッファ
  - 最大保持フレーム数: `config.json`で設定可能（デフォルト: 100フレーム）
  - メモリ効率を考慮した実装
  - リアルタイムモード時は最新フレームのみ保持
  - 再生モード時は指定フレーム数を保持

### `RealtimeVideoProcessor`との統合
- `RealtimeVideoProcessor`は既存のまま使用
- **元フレーム**: `frame_queue`から直接取得（処理の成功/失敗に関係なく表示）
- **差分画像**: `frame_buffer`から処理結果を取得（処理成功時のみ表示）
- GUIからの制御は`start()`/`stop()`メソッドを呼び出す

### 処理結果の状態管理
- `frame_buffer`に含まれる処理結果には、処理状態を含める:
  ```python
  {
      "status": "success" | "error" | "no_difference",
      "error_message": "...",  # エラー時のみ
      "original_frame": ...,
      "difference": ...,
      ...
  }
  ```
- GUI側で`status`を確認し、適切に表示/エラーメッセージを表示

## 8. 注意事項

- `RealtimeVideoProcessor`は既存のまま使用（変更なし）
- OpenCVの`cv2.imshow`は使用せず、PyQtで表示
- 画像のBGR→RGB変換が必要（OpenCVはBGR、PyQtはRGB）
- スレッドセーフティに注意（GUI更新はメインスレッドで）
- **元フレームの表示**: 処理の成功/失敗に関係なく、カメラからの生フレームを常に表示
- **差分画像の表示**: 処理が成功した場合のみ表示し、失敗時はエラーメッセージを表示
- **エラーハンドリング**: 処理結果の`status`を確認し、適切にエラーメッセージを表示

## 9. 差分画像の保存について

- **現状の保存方針を維持**:
  - 差分が検出されたフレームのみ、差分画像を保存
  - 差分が検出されなかったフレームは、元フレームのみアーカイブに保存（差分画像は保存しない）
- 再生モードで表示される過去フレームは、既に保存されたフレームのみ表示可能

## 10. 実装の技術的考慮事項

### メモリ管理
- 過去フレームの保持は、メモリ使用量を考慮して実装
- バッファサイズは`config.json`で設定可能にする
- 高解像度・長時間処理時のメモリ制限を考慮

### パフォーマンス
- バッファへの書き込みオーバーヘッドを最小化
- スライダー操作時のフレーム取得を高速化
- リアルタイムモード時のパフォーマンスへの影響を最小化

## 11. リアルタイムカメラ映像ウィンドウ（別ウィンドウ）

### 概要
カメラからの生映像をリアルタイムで表示する別ウィンドウ機能。`RealtimeVideoProcessor`の`frame_queue`からフレームを取得して表示することで、カメラの二重使用を回避し、リアルタイム性を確保します。メイン処理が動作している場合のみ表示可能です。

### 実装方針
- **別ウィンドウ方式**: メインウィンドウとは独立した`QMainWindow`または`QDialog`として実装
- **カメラの共有**: `RealtimeVideoProcessor`の`frame_queue`からフレームを取得して表示
  - 新しい`VideoCapture`を開かず、メイン処理とカメラを共有
  - カメラの二重使用による排他制御の問題を回避
- **処理との連携**: `RealtimeVideoProcessor`が動作している場合のみ表示可能

### 機能
1. **リアルタイム映像表示**
   - メイン処理の`frame_queue`から取得したフレームをリアルタイムで表示（処理を経由しない、遅延最小）
   - タイムスタンプ表示（オプション）
   - ウィンドウタイトル: 「LogSense v5 - リアルタイムカメラ映像」

2. **コントロール**
   - メインウィンドウのコントロールパネルに「リアルタイム映像」ボタンを追加
   - ボタンクリックで別ウィンドウを開閉
   - メイン処理が動作している場合のみ表示可能
   - ウィンドウを閉じてもメイン処理は継続

### クラス構成
```python
class FrameBroadcaster:
    """フレームを複数のコンシューマーに配信"""
    - subscribe(): 新しい購読者を追加（独立したキューを返す）
    - broadcast(frame): 全購読者にフレームを配信

class LiveCameraWindow(QMainWindow):
    """リアルタイムカメラ映像表示ウィンドウ"""
    - FrameBroadcasterから購読した独立したキューからフレームを取得
    - リアルタイム映像表示
    - タイムスタンプ表示（オプション）
```

### 実装の詳細

#### カメラアクセス
- **カメラの共有**: `RealtimeVideoProcessor`のフレームブロードキャスト機能を使用
  - 新しい`cv2.VideoCapture`インスタンスを開かない
  - メイン処理と同じカメラストリームを使用
  - カメラの二重使用による排他制御の問題を回避

#### フレームのブロードキャスト
- **FrameBroadcaster**: フレームを複数のコンシューマーに配信するクラス
  - 各コンシューマー（メインウィンドウ、リアルタイム映像ウィンドウなど）が独立したキューを持つ
  - `RealtimeVideoProcessor`の`_capture_loop`で取得したフレームを全購読者に配信
  - フレームの競合を回避（各コンシューマーが独立したキューから取得）

#### スレッド処理
- **フレーム取得**: `FrameBroadcaster`から購読した独立したキューから取得
- **メインスレッド**: GUI更新（PyQt）
- **通信**: ブロードキャスト経由でフレームを取得（各コンシューマーが独立したキュー）
- **更新**: `QTimer`で定期的に購読キューをチェックしてフレームを更新

#### メインウィンドウとの統合
- メインウィンドウのコントロールパネルに「リアルタイム映像」ボタンを追加
- ボタンの状態: 「表示」/「非表示」で切り替え
- ウィンドウの開閉状態を管理
- **前提条件**: メイン処理（`RealtimeVideoProcessor`）が動作している必要がある
  - メイン処理が停止している場合、エラーメッセージを表示

#### RealtimeVideoProcessorとの統合
- `RealtimeVideoProcessor`に`FrameBroadcaster`を追加
- `_capture_loop`で取得したフレームを`broadcast`で全購読者に配信
- メインウィンドウと`LiveCameraWindow`はそれぞれ`subscribe()`で独立したキューを取得

### 実装の優先順位
- **Phase 1.5（基本機能の拡張）**: リアルタイムカメラ映像ウィンドウの実装
  1. `FrameBroadcaster`クラスの作成
  2. `RealtimeVideoProcessor`に`FrameBroadcaster`を統合
  3. `LiveCameraWindow`クラスの作成（ブロードキャストから購読）
  4. メインウィンドウの`update_frames`をブロードキャスト方式に変更
  5. メインウィンドウに「リアルタイム映像」ボタンを追加
  6. ウィンドウの開閉機能
  7. メイン処理が動作していない場合のエラーハンドリング

### 注意事項
- **メイン処理の依存**: メイン処理（`RealtimeVideoProcessor`）が動作している必要がある
  - メイン処理が停止している場合、リアルタイム映像は表示できない
- **フレームの共有**: メイン処理の`FrameBroadcaster`から配信されるフレームを使用
  - 各コンシューマーが独立したキューを持つため、フレームの競合を回避
  - フレームレートはメイン処理に依存
- **メモリ効率**: カメラの二重使用を回避するため、メモリ使用量は最小限
  - 各コンシューマーのキューは最大2フレームまで保持（古いフレームは自動破棄）

### 技術的な考慮事項
- **フレームのブロードキャスト方式**: `FrameBroadcaster`を使用してフレームを配信
  - メイン処理の`_capture_loop`が取得したフレームを`broadcast`で全購読者に配信
  - 各コンシューマーが独立したキューを持つため、フレームの競合を回避
  - Observerパターンに基づいた実装
- **遅延**: メイン処理の`_capture_loop`から取得するため、メイン処理のフレームレートに依存
  - ただし、処理を経由しないため、表示までの遅延は最小限
  - 各コンシューマーのキューは最新フレームのみ保持（古いフレームは自動破棄）
- **スケーラビリティ**: 複数のコンシューマーを追加しやすい設計
  - 将来的に複数のリアルタイム映像ウィンドウを開くことも可能
- **エラーハンドリング**: 
  - メイン処理が動作していない場合の処理
  - `FrameBroadcaster`が初期化されていない場合の処理
  - フレームが取得できない場合の処理
